4. 核心模块详解

4.1 scanner.py — 递归扫描引擎

  • 核心函数：scan_path(path) → _scan() 递归调用
  • 扫描策略：使用 os.scandir() 遍历，统计每个文件夹（含子树）的总大小
  • 符号链接：检测 symlink 和 junction，记录但不递归遍历（避免重复计算和死循环）
  • 权限处理：捕获 PermissionError/OSError，标记为不可访问
  • 深度限制：默认 max_depth=50，防止极深路径栈溢出
  • 取消机制：should_stop 回调 + ScanAborted 异常，实现安全终止
  • 输出格式：树形字典节点 {name, path, size_bytes, size_human, children, ...}

4.2 knowledge_base.py — 规则库引擎

  • 规则来源：从 rules.json 加载规则列表和保护名单
  • 匹配类型：支持 4 种匹配模式
    • path：路径尾部匹配（如 AppData\Local\Temp）
    • name：目录名精确匹配（如 pip）
    • endswith：文件名后缀匹配（如 .log）
    • name_under_parent：父目录下特定名称匹配
  • 分类结果：返回 {category, description, advice, cleanable}
  • 保护名单：系统关键目录（Windows、ProgramData 等）强制返回 never，禁止删除

4.3 analyzer.py — 分析编排层

  • 两阶段分析：
    1. classify_tree()：规则库分类（必须成功，失败则整扫失败）
    2. ai_describe()：AI 识别（尽力而为，失败不影响已生成的目录树）
  • AI 识别策略：
    • 第一层目录（depth=1）：无论大小，全部强制 AI 识别
    • 深层（depth 2~max_auto_depth）：仅未识别且 >1GB 的大文件夹自动分析
    • 更深的文件夹：用户点「🤖 AI分析」按钮按需触发

4.4 ai_describer.py — DeepSeek AI 封装

  • 批量分析：describe_batch() 每批 30 个文件夹，构建 prompt → 调 API → 解析 JSON 响应
  • 单个分析：analyze_one() 用户点击触发，返回 summary/level/deletable/impact/confidence
  • 缓存机制：cache.json 磁盘缓存，命中即返回，节省 API 额度
  • 重试策略：网络连接错误自动重试 3 次，指数退避
  • 代理支持：通过 DEEPSEEK_PROXY 环境变量配置公司网络代理
  • JSON 解析：容错处理，提取文本中第一个 {...} 块

4.5 app.py — Flask 后端主程序

  • 扫描状态管理：全局 scan_state 字典 + 代次机制（scan_gen），支持取消/替换
  • 日志系统：内存缓冲（最多 50 万条）+ 落盘（scan_debug.log），支持增量拉取
  • 进度节流：每 0.35s 或每 150 个目录才记一条摘要日志，避免日志风暴
  • AI Key 管理：联网测试 → 写回 .env → 重建客户端，全流程热更新
  • 安全护栏：删除/打开操作限制在扫描根目录内，保护名单目录禁止删除
  • 树分页：TREE_MAX_DEPTH 折叠深层节点，前端按需展开，避免 300MB JSON 撑爆浏览器

4.6 report_exporter.py — HTML 报告生成

  • 自包含报告：CSS + JS + 数据全部内联，可脱离后端直接在浏览器打开
  • 聚焦版：export_focused_report_html() 只输出最大的 500 个 + 全部已识别文件夹
  • 交互功能：搜索、分类筛选、AI 按需分析（浏览器端直连 DeepSeek API）

5. API 接口

端点方法说明
/api/key_statusGET检查服务端是否有可用的 DeepSeek Key
/api/set_keyPOST提交 Key → 联网测试 → 写回 .env → 重建 AI 客户端
/api/healthGET返回 AI 启用状态和阈值
/api/scanPOST发起扫描（后台线程），支持 force 覆盖正在进行的扫描
/api/statusGET增量拉取扫描日志和状态（?after=N）
/api/treeGET获取完整目录树（折叠深层，仅前 3 层完整）
/api/tree_nodeGET按需展开：返回指定路径下一级子节点（?path=）
/api/analyzePOST对单个文件夹调 DeepSeek 分析用途/可否删除/影响
/api/reportGET下载/查看自包含 HTML 报告
/api/openPOST在本地资源管理器打开指定文件夹
/api/deletePOST删除文件夹（默认进回收站，失败回退永久删除）

9. AI 单个分析详细流程

当用户在前端点击某个文件夹的「🤖 AI分析」按钮时，触发 analyze_one()，它比批量识别多一个 impact（删除影响） 字段。

9.1 批量 vs 单个分析对比

对比维度describe_batch (批量)analyze_one (单个)
触发时机扫描完成后自动执行用户点击「🤖 AI分析」按钮
一次处理最多 30 个/批，循环分批1 个文件夹
返回字段summary, software, level, deletable, confidence同左 + impact（删除影响）
缓存标记ai_analyzed: trueai_analyzed_one: true

错误处理单批失败跳过，继续下一批直接报错返回前端
Prompt 风格编号列表 "1. 这个文件夹是干什么的？..."单条详细提问

10. 设计亮点

  • 渐进式 AI 分析：第一层全部识别 → 深层仅大文件夹自动分析 → 更深按需点击，避免巨树全量调 API 卡死
  • 代次取消机制：每次新扫描递增 scan_gen，旧 worker 在检查点安全退出，无需 kill 线程
  • 树分页下发：TREE_MAX_DEPTH=3 折叠深层节点，前端按需 /api/tree_node 展开，避免 300MB JSON 崩溃浏览器
  • 日志涓流渲染：后端每批 60 条 + 前端 rAF 每帧 12 条，日志更新平滑不卡
  • 自包含报告：CSS+JS+数据全部内联，可脱离后端直接发送给他人打开
  • 安全护栏：删除/打开限制在扫描根目录内，保护名单硬编码，防止误删系统目录
  • AI Key 热更新：前端提交 → 联网测试 → 写回 .env → 重建客户端，无需重启进程
  • 缓存断点续传：AI 分析结果每批落盘 cache.json，中断后重扫不重调 API
